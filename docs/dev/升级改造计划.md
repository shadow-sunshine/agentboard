# Multi_Agent_Orchestration 改造计划（课程 demo → 可投递真项目）

> 目标：把现有课程演示（agently + acp + 5 个线性脚本）重构成**原创、可测试、有评测、有 CI** 的第 3 个简历项目，工程交付标准对齐 PDD（163 测试 + CI + 真实数据）。
> 定位口径（面试诚实边界）：基于课程范式**重写成原创实现**，不写"独立从零发明"，但所有代码、测试、评测均为本人产出。

## 2. 去 agently 方案（主 Agent 换 LangGraph）

现有 `agently.create_agent().info(...).output(schema)` 三段式，替换点：

- **配置**：删 `Agently.set_settings`，改 `langgraph` / `openai` SDK 初始化（复用投研助手的 LLM client 封装）。
- **结构化输出**：`agently` 的 `.output({...})` 字段契约 → 等价改成 **pydantic model + `response_format`**（或 LangGraph 的 structured output）。`TaskCard` 等 dataclass 直接复用，模型输出经 pydantic 校验后转 dataclass。
- **编排**：`04` 的 `TriggerFlow` 三阶段 chunk → 用 **LangGraph StateGraph** 重写（`plan_board → dispatch_tasks → synthesize_report` 为节点，`decide_board_action` 为条件边）。
- **子 Agent 不动**：`acp` 是真实协议库，保留；仅把 `forbidden` 里的"不读文件/不跑命令/不联网"放开，让子 Agent 真实调研。

> 收益：主从都用"主流栈"，面试官不会卡在 agently；LangGraph 与投研助手一致，简历两个项目技术叙事连贯。

## 3. 评测套件设计（核心差异化，对齐"可验证性 25%"权重）

`eval/run_eval.py` 跑固定场景集，输出可回归的数字：

| 指标 | 断言 | 量化目标 |
|---|---|---|
| 看板结构合法率 | `validate_model_board` 全过 + `ensure_board_is_dag` 无环 | 100% |
| 上下文隔离率 | 子 Agent 收到的 `WorkerTaskInput` 不含未声明依赖字段 | 100% |
| 失败兜底正确率 | 注入 worker 失败，断言 `retry` 触发且 `MAX_ATTEMPTS` 后 `blocked` | 100% |
| 端到端完成率 | 复杂目标最终报告含 required sections（摘要/事实/缺口/风险/下一步） | ≥90% |
| **上下文污染对比** | 同目标"有隔离 vs 无隔离"两次跑，统计下游子 Agent 误引无关信息的比例 | 污染率 ↓（如 35%→5%） |

场景集至少 8 个：3 个正常复杂目标 + 3 个含失败/环依赖/越权 + 2 个跨域（验证项目隔离）。

## 4. 分阶段执行计划（每阶段带验收门，先验再下一步）

**P0 · 抽包 + 去 agently（等价跑通）**
- 把 5 脚本的 dataclass / 函数搬进 `src/multi_agent/` 对应模块，行为不变。
- 主 Agent 换 LangGraph，跑通原 5 步等价输出（对比 `.demo_runs/` JSON 产物）。
- *验收*：原 5 脚本的 JSON 产物可由新包复现。

**P1 · 测试 + 评测 + CI**
- 写 `tests/` ≥30 单测（DAG/护栏/隔离/兜底/ACP 生命周期，用 mock）。
- 写 `eval/` 场景集 + `run_eval.py`，出第 3 节数字。
- 接 GitHub Actions：push 跑 `pytest` + `python eval/run_eval.py`。
- *验收*：CI 绿；评测指标达标；README 贴上数字。

**P2 · 真子 Agent + 服务化**
- 放开 `forbidden`，子 Agent 真实调研（接本地 Codex / 真搜索）。
- `server.py` FastAPI 暴露 board + `worker_delta` 流式。
- *验收*：一个真实团建目标端到端出报告；接口能看实时 board。

**P3（可选）· 吸记忆子模块**
- 把 Hermes 的四层记忆 + 两条召回，作为主 Agent 的"召回增强"挂到 `src/multi_agent/memory/`。
- *验收*：主 Agent 开局自动带相关长期记忆；输出差异可观测。

## 6. 风险与诚实边界（面试 defense）

- 起源是课程范式演示 → 讲成"基于公开范式重写原创实现"，不谎称从零发明。
- 子 Agent 放开工具后可能慢/不稳 → 评测用 mock worker 保证确定性，真实 worker 仅 demo。
- 仍非线上产品（无用户系统/持久化 DB）→ 卖点始终是"Agent 工程纪律"，不是用户量。
